## 🎯 Qué se pedía

Realizar tres retos para aprender a recuperar archivos borrados utilizando Git. Primero recuperar archivos sin Internet, después reconstruir un repositorio completo desde GitHub y, por último, comprobar qué ocurre cuando borramos archivos que no hemos subido mediante `push`.

## ⌨️ Comandos y pasos importantes

- `git status` — muestra los cambios y archivos eliminados del repositorio.
- `git restore .` — recupera todos los archivos borrados desde el último commit.
- `pwd` — muestra la ubicación actual en la terminal.
- `git clone` — descarga un repositorio completo desde GitHub.
- `git log --oneline` — muestra el historial de commits.
- `git commit` — guarda los cambios en el historial del repositorio.
- `git push` — sube los cambios a GitHub.
- `q` — permite salir del paginador de Git.

## 🤔 Respuestas a las preguntas

1. El Reto 1 se puede solucionar sin Internet porque el historial de Git está guardado en la carpeta oculta `.git` de nuestro ordenador. En cambio, en el Reto 2 borramos toda la carpeta, incluida `.git`, por lo que tenemos que recuperar el repositorio desde GitHub.
2. Faltó hacer `commit` y `push`. Como las notas solamente estaban guardadas en mi ordenador y nunca se subieron a GitHub, al borrar la carpeta se perdieron y no se pudieron recuperar.
3. Si trabajas en el aula y no haces `push`, los cambios se quedan guardados solamente en el ordenador del centro. Cuando llegues a casa no aparecerán porque nunca se subieron a GitHub. Por eso hay que hacer `commit` y `push` al terminar cada sesión de trabajo.
