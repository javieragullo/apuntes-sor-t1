## ⌨️ Comandos y pasos importantes

- `git --version` — comprueba que Git se ha instalado correctamente y muestra su versión.
- `ssh-keygen -t ed25519 -C "tu-correo-de-github"` — genera un par de claves SSH (pública y privada) nuevas para el ordenador de casa.
- `cat ~/.ssh/id_ed25519.pub` — muestra por pantalla la clave pública para poder copiarla y añadirla a GitHub.
- `git config --global user.name "Javier Agulló Ivorra"` / `git config --global user.email "tu-correo"` — configura el nombre y correo asociados a los commits de Git en el equipo local.
- `ssh -T git@github.com` — verifica que la autenticación por SSH contra GitHub funciona correctamente.
- `mkdir -p RUTA_SOR/Boveda_SOR/00_Apuntes` y `mkdir -p RUTA_SOR/Boveda_SOR/01_Practicas` — crea las carpetas base de la bóveda en una ruta local fuera de OneDrive.
- `git clone git@github.com:TU-USUARIO/apuntes-sor-t1.git Trimestre_1` — clona el repositorio personal de apuntes renombrando la carpeta resultante a `Trimestre_1`.
- `git clone git@github.com:TU-USUARIO/bloque-0-prerequisitos.git B0_Prerrequisitos` (y sus equivalentes para B1 y B2) — descarga los repositorios de prácticas dentro de `01_Practicas/`.

## 🤔 Respuestas a las preguntas

1. **¿Por qué clonas desde GitHub en vez de copiar con pendrive?**
   Porque en GitHub es donde está almacenada la versión actualizada y buena del trabajo del centro; clonar asegura que ambas copias estén sincronizadas e idénticas mediante el control de versiones.
2. **¿Por qué generas una clave SSH nueva en casa?**
   Por seguridad, ya que las claves privadas nunca deben copiarse ni transportarse de un ordenador a otro. Cada equipo debe tener su propia clave registrada de forma independiente en GitHub.
3. **¿Dónde NO debe estar la bóveda?**
   No debe estar dentro de carpetas sincronizadas con OneDrive (como Escritorio o Documentos si tienen el icono de la nube), porque OneDrive y Git entran en conflicto y generan archivos duplicados.
